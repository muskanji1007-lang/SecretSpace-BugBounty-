2. Detailed Bug Reports & Reproduction Specifications
BUG-01 Category Filter Trap on Empty Search
Low Confirmed
Component: ExplorePage.jsx (Line 63-66)
Classification: UI State Synchronization
Reproduction Steps:
  1. Navigate to the Explore page.
  2. Click any category tile (e.g. Hostel Life).
  3. In search input, enter a string with 0 matches (e.g. xyz999).
  4. The EmptyState appears. Click the "Clear Search" button.
Expected: Search input clears AND active category resets to "All", restoring full feed results.
Actual: Search text clears but category filter remains set, leaving the screen permanently empty until manual category click.
// Fix in ExplorePage.jsx: const handleClear = () => { setSearchQuery(''); setActiveCategory('all'); // Explicitly reset category filter setSearchParams({}); };
BUG-02 In-Text Hashtags Unclickable in Confession Body
Low Confirmed
Component: PostCard.jsx (Line 72-84)
Classification: Frontend Navigation / UX
Reproduction Steps:
  1. Scroll through the Home feed to any post containing inline tags like #Midterms or #CampusCrush.
  2. Hover and click over the hashtag keyword inside the confession text.
Expected: Cursor shows pointer, clicking navigates to /explore?q=%23Midterms.
Actual: Rendered as static <span> without click handler or router navigation.
// Fix in PostCard.jsx: <button onClick={(e) => { e.stopPropagation(); navigate(`/explore?q=${encodeURIComponent(tag)}`); }} className="text-purple-600 hover:underline cursor-pointer"> {tag} </button>

BUG-07 Negative Counter on Pasted Content Exceeding 500 Chars
Low Confirmed
Component: CreatePostBox.jsx (Line 89-94)
Classification: Input Constraint Handling
Reproduction Steps:
  1. Copy a block of text containing 560 characters from any text editor.
  2. Paste the content into the Confession textarea.
  3. Check the character counter below the input.

Actual: Textarea allows 560 characters and counter displays -60 / 500 with no truncation.
// Fix in CreatePostBox.jsx: <textarea maxLength={500} onChange={(e) => setContent(e.target.value.slice(0, 500))} />

BUG-09 Lexicographical Sorting on "Top" Confessions
Medium Confirmed
Component: AppContext.jsx (Line 134-142)
Classification: Algorithm / Data Type Bug
Reproduction Steps:
  1. Ensure feed has three posts with upvotes: 9, 15, and 102.
  2. In the feed sorting dropdown, select "Top".
Expected: Numeric sort order: 102, 15, 9.
Actual: Sorted alphabetically as strings: "9" appears ahead of "15" and "102".
// Fix in AppContext.jsx: case 'top': return [...list].sort((a, b) => Number(b.upvotes) - Number(a.upvotes));
BUG-10 Multi-Tab Duplicate Poll Voting
Medium Confirmed
Component: PollWidget.jsx (Line 60-72)
Classification: State Race / Concurrency
Reproduction Steps:
  1. Open the same poll URL in Tab A and Tab B of the same browser session.
  2. Cast a vote in Tab A (e.g. Option 1).
  3. Without refreshing, switch to Tab B and vote for Option 2.
Expected: Tab B detects prior vote via local storage or backend check and blocks repeat submission.
Actual: Vote executes in Tab B because hasVoted flag is isolated in transient React component memory.
// Fix in PollWidget.jsx: // Sync poll votes with localStorage or AppContext global userVotes map const hasVoted = Boolean(userVotes[poll.id] || localStorage.getItem(`voted_poll_${poll.id}`));
BUG-11 Premature "Copied" Toast on Clipboard Rejection
Low Confirmed
Component: PostCard.jsx (Line 110-116)
Classification: Asynchronous Promise Handling
Reproduction Steps:
  1. Revoke clipboard permissions in browser settings (or use an insecure iframe).
  2. Click the "Share" button on any confession card.
Expected: Toast informs user that clipboard copying was blocked or failed.
Actual: Green toast announces "Link copied to clipboard!" synchronously before the rejected promise resolves.
// Fix in PostCard.jsx: try { await navigator.clipboard.writeText(shareUrl); showToast('Link copied to clipboard!', 'success'); } catch (err) { showToast('Could not copy link automatically', 'error'); }
BUG-12 Settings Privacy Toggles Revert on Page Navigation
Low Confirmed
Component: SettingsPage.jsx (Line 31-40)
Classification: State Lifecycle / Persistence
Reproduction Steps:
  1. Open the Settings page.
  2. Toggle "Blur Sensitive Topics" to OFF.
  3. Click Explore in the sidebar, then return immediately to Settings.
Expected: The toggle switch remains in the OFF position.
Actual: The switch resets back to ON because state was initialized with static defaults on unmount.
// Fix in SettingsPage.jsx: // Store toggle preferences in AppContext state and sessionStorage: const [blurSensitive, setBlurSensitive] = useState(() => JSON.parse(sessionStorage.getItem('settings_blur') ?? 'true') );

3. High-Priority Architectural & Security Observations (Isolated)

As required by the evaluation criteria, non-functional security vulnerabilities and server-level architectural concerns are documented separately so they are not conflated with minor UI/functional bugs.

Issue Area Risk Level Affected Layer Recommendation
JWT Secret Default High server/src/middleware/auth.js Avoid hardcoded fallback string in production; enforce strict runtime exception if JWT_SECRET is undefined.
Stateless Rate Limiting Medium server/src/middleware/rateLimiter.js Express in-memory rate limiter does not share state across Vercel serverless lambda instances. Integrate Upstash Redis for distributed throttling.
Anonymity Projection Medium server/src/controllers/postController.js Ensure MongoDB projection strictly strips author user IDs before sending JSON payloads to public feeds (enforced in latest release).
